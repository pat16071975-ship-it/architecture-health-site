## Цели в интерфейсе Метрики

Создать три цели типа «Целевое событие» (в некоторых версиях интерфейса «JavaScript-событие»), условие «совпадает»:

| Название | Идентификатор |
| --- | --- |
| Открытие окна записи | booking_open |
| Переход к записи в Medflex | booking_medflex |
| Нажатие на телефон | phone_click |

События обозначают нажатия, не состоявшуюся запись или звонок. Никакие значения форм или данные пациентов в reachGoal не передаются. Стандартный счётчик учитывает URL, referrer и поведение на публичных страницах; это не заявление об отсутствии технических данных посещения. Доступ к аккаунту Метрики отсутствует: цели нужно создать владельцу; код их автоматически не создаёт. Автоматические цели Метрики могут отображаться отдельно; не суммировать их с одноимёнными ручными действиями.

## UTM

utm-links.csv содержит готовые входящие ссылки. Размещать в карточках Яндекс Карт, 2ГИС, профилях соцсетей, подписи писем и QR. Внутренние ссылки сайта не размечать. Для публикаций задавать отдельный utm_campaign, для сравнения вариантов — utm_content. Не включать ФИО, телефоны, диагнозы или другие данные пациентов. Google пока не используется. Внешние профили и подписи этим установщиком не меняются.

## Установка

Только root на az-server, --check затем --apply. Точечные вставки с проверкой исходных и конечных SHA256, lock, backup /var/backups/azmednsk/metrika-*, проверка HTTPS каждой страницы и JS. При ошибке изменения автоматически откатываются. DNS, nginx, серверные службы и базы не меняются. Отложенную замену info@expertstom.ru не выполнять в этом пакете.

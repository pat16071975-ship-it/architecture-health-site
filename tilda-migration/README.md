# Архитектура здоровья — подготовка переноса с Tilda

Самостоятельная статическая реализация текущего сайта. Это первая тестовая
сборка, а не разрешение заменить работающий сайт.

- 75 адресов из опубликованной карты сайта и 3 страницы каталога специалистов.
- Тексты, собственные фотографии клиники, локальные шрифты и изображения.
- Свои HTML/CSS/JavaScript: меню, фильтры команды, диалоги и адаптивные макеты.
- Авдалиè и Сергеев не включены. У трёх обновлённых портретов сохранено кадрирование сверху.
- На всех страницах `noindex,nofollow`; robots.txt запрещает индексацию теста.
- Базы данных и Supabase для этой сборки не требуются.

## Тестовый запуск

Из каталога `tilda-migration` сначала восстановить медиа, если это Git checkout:

```
python3 tools/restore_media.py
```

В переданном архиве все медиа уже включены. Затем:

```
python3 -m http.server 8080 --directory public
```

Для nginx корень тестового сайта — `public`. При маршрутизации использовать
`try_files $uri $uri/ =404` и `error_page 404 /404.html`. Отдельный тестовый
виртуальный хост согласовать до настройки. Основной домен не переключать.

## Границы первой сборки

Оформление восстановлено по опубликованным визуальным параметрам. Сравнение
страниц в браузере на настольном и мобильном экранах ещё необходимо. Локальные
file:// страницы недоступны для облачного браузера; проверять на отдельном HTTP
тестовом адресе. Сборку пока нельзя считать визуально утверждённой.

Формы Tilda не скопированы. Кнопки открывают окно со ссылкой на действующий
Medflex и телефоном; собственная отправка заявок, уведомления и согласия требуют
отдельной настройки до переноса. Никаких тестовых записей не отправлено.

Карта Яндекса подключена отдельным iframe. Видео клиники пока имеет оригинальную
обложку; видеоплеер необходимо подключить и проверить. Новости и некоторые
динамические блоки требуют сверки. `validation.json` содержит найденные проблемы
ссылок исходного сайта и результата сборки. Эти проблемы не скрывать.

Архив исходных страниц используется только как доказательство при подготовке,
не размещается в `public`, не включается в поставку и не служит рабочим кодом.
Ни один скрипт, CSS-файл или шаблон Tilda не используется в работающей копии.

## Редактирование

Рабочие страницы — `public/**/index.html`, свои общие правила — `site.css`,
`layouts.css` и `site.js`. Все URL сохранены. Инструмент build.py используется
только для начальной подготовки из локального архива; повторный запуск после
ручного редактирования перезапишет HTML. Для последующей работы менять рабочие
файлы в Git, а не пересобирать из Tilda.

Оригиналы медиа включены в поставку. `media-manifest.json` фиксирует SHA256
каждого файла. В Git хранятся код и манифест; крупные файлы медиа поставляются
отдельно в архиве и после размещения читаются только с собственного хостинга.

Переключение домена — только после проверки тестовой копии и отдельной прямой
команды владельца. До этого действующий сайт работает на Tilda.

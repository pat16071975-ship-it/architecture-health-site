# Медрасходка: автоматический разбор следующих PDF

Статус: **SOURCE-ONLY**. Описание доработки исходников от 26.11.2026;
не является независимым аудитом, разрешением выпуска или подтверждением
установки. Версии: `RECOGNITION_VERSION = 2`, `EXTRACTOR_VERSION = 6`.
Реальные документы, реквизиты и результаты их частной сверки в этот файл
и публичные тестовые данные не включены.

## Пользовательский поток

1. Загруженный оригинал сохраняется во входящих. Разбор использует уже
   сохранённые байты PDF и не требует повторно присылать файл.
2. Явное действие «Разобрать документ» запускает последовательные POST
   по страницам. Прямой GET, просмотр и перезагрузка страницы не запускают
   распознавание и не записывают данные. Повторный запуск доступен через
   «Обновить разбор».
3. Локальный OCR строит предложения по строкам и реквизитам. Для таблиц
   с видимой сеткой дополнительный обработчик ищет ячейки непосредственно
   на изображении, включая ячейки, пропущенные первым распознаванием.
4. Пользователь получает таблицу: название, количество, единица,
   стоимость строки, раздел. При достаточных основаниях заполнены также
   реквизиты и сопоставление со справочником. Неясные поля и расхождения
   обозначены сообщениями.
5. Разбор сохраняется как черновик. Отметку проверки ставит пользователь
   после сверки. Сохранение, автоматический выбор раздела и статус
   проверенного документа не создают материал, приход или финансовую запись.

## Извлечение из изображения и неопределённость

`medical_supplies_ocr_image.py` компенсирует небольшой наклон, выделяет
линии таблицы, формирует представления ячеек для повторного Tesseract
и сопоставляет числовые чтения. Координаты принятого текста возвращаются
в систему координат исходного растра. Предложения сохраняют ссылки
на исходные OCR-строки; данные не подставляются по имени файла, поставщику,
артикулу или заранее известному итогу.

Уверенность Tesseract, согласие повторных чтений и границы ячейки используются
как фильтры. Это не вероятность правильности документа и не основание
автоматически помечать страницу проверенной. Нечитаемые и противоречивые
числа остаются неизвестными. Назначение денежной колонки подтверждается
её заголовком: явная стоимость с налогом — `printed_gross`, единственная
сумма без противоречивых уточнений — `printed_single_total`. Сумма без налога,
отдельный налог и неоднозначный заголовок не становятся стоимостью с налогом.
Из цены и количества стоимость не вычисляется; налог не достраивается.

`medical_supplies_ocr_quality.py` сравнивает сумму строк с явно распознанным
печатным итогом через `Decimal`. Для сравнения должны быть прочитаны
название, положительное количество, единица и стоимость каждой строки.
Строки с решением «Пропустить» остаются в сверке с полным печатным итогом,
а исключение показывается отдельно. Отсутствие итога, неполные поля,
расхождение сумм и невыбранные разделы дают сообщения. Совпадение суммы
само по себе не доказывает полноту названий, страниц или правильность количества.

Тип документа, поставщик, номер, дата и пагинация предлагаются из явно
прочитанных реквизитов. После повторного OCR дата и пагинация должны совпасть
в первичном и выровненном чтениях; конфликт или отсутствие подтверждения
оставляет поле неизвестным. Сообщения собраны в раскрываемый блок над
таблицей, чтобы не отодвигать товары длинным перечнем замечаний.
Полнота страниц проверяется в пределах однозначной
идентичности документа: одинаковые порядковые номера у разных документов
не объединяются. Неизвестные реквизиты или пагинация не позволяют объявить
документ полным.

## Автоматический выбор материала и раздела

`medical_supplies_ocr_enrichment.py` использует последовательные основания:

- Однозначное совпадение нормализованных названия и единицы с действующим
  материалом. Несколько совпадений или исключённый материал не разрешаются
  произвольным выбором.
- Однозначный раздел из ранее **проверенных** строк с теми же названием
  и единицей. Текущий документ и непроверенные черновики не обучают подбор;
  противоречивая история сохраняет неопределённость.
- Правило по виду товара, только если оно однозначно указывает на уже
  существующий путь папок. Новые папки автоматически не создаются,
  фиксированные числовые идентификаторы папок не используются.

Из истории и справочника не переносятся количество, цена, стоимость или
флаг проверки. Это данные текущего документа. Сохранённый ручной выбор
не заменяется новым автоматическим предложением.

## Повторное распознавание и сохранность

Старые автоматические предложения можно пересчитать новой версией движка.
Первичный OCR сохраняется в `previous_ocr` без рекурсивного накопления копий.
Если уже существуют ручные `rows` или `header`, даже пустые `[]` или `{}`,
они имеют приоритет; новый результат помещается в отдельное поле
`automatic`. Исходная карта строк, ручные значения и отметки не затираются.

При временной ошибке дополнительного OCR сохраняется первичный результат
с пояснением и `recognition_retryable = true`. Следующее явное обновление
повторяет распознавание даже при текущей версии движка. Неподдерживаемая
сетка или неоднозначные заголовки дают объяснённый резервный результат;
они не должны вызывать бесконечный автоматический повтор.

Если первая страница обновилась, а следующая завершилась ошибкой,
показанная старая форма остаётся заблокированной до загрузки свежего
представления через «Показать сохранённые строки». Повторная попытка OCR
не снимает эту блокировку. Скрытая версия старой формы не подменяется
новой версией документа.

Действуют прежние `accounting` и права редактирования/управления входящими,
проверка CSRF и конфликта версии до OCR. Перед распознаванием сверяются
размер и SHA-256 оригинала; перед записью транзакция повторно проверяет
версию и SHA. Черновик и событие истории сохраняются атомарно.
`original_bytes` не изменяются. GET возвращает `private, no-store`.
Новых таблиц, миграций и складских проводок этот поток не требует.

## Зависимости и пределы

- Только PDF размером до `20 * 1024 * 1024` байт, от 1 до 20 страниц;
  одна страница на POST, один OCR одновременно под файловой блокировкой.
- Основные локальные инструменты: Poppler, Tesseract с `rus` и `eng`,
  `prlimit`; Python-зависимости — `numpy==2.2.6` и
  `opencv-python-headless==4.12.0.88` вместе с существующим requirements.
- Дополнительное восстановление рассчитано на таблицы с различимой сеткой.
  Отсутствующая сетка, повреждённый заголовок и плохой скан ограничивают
  автозаполнение; первичный обработчик остаётся резервным вариантом.
- Внешние операции страницы используют общий дедлайн 25 секунд,
  каждый запуск получает оставшийся бюджет. Это не обещание времени всего
  HTTP-запроса: обработка изображения и сохранение также занимают время.
  Сохраняются ограничения памяти, числа слов/ячеек/строк, размеров временных
  файлов и фиксированные команды без shell.
- Оригиналы не передаются внешней модели или OCR-сервису; API-ключ не нужен.

## Воспроизводимая проверка

Команды ниже предназначены для локального checkout или CI, не для рабочего
сервера. Используется Python 3.13, как в профильном workflow. Из корня
репозитория подготовить окружение на Ubuntu:

```bash
python3.13 -m venv .venv-medical
. .venv-medical/bin/activate
python -m pip install -r az-baze-auth/requirements.txt
python -m pip install playwright
sudo apt-get update
sudo apt-get install -y --no-install-recommends util-linux poppler-utils tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
python -m playwright install --with-deps chromium
cd az-baze-auth
```

Профиль OCR включает реальные локальные инструменты на **синтетических**
PDF и изображениях. Переменная `AZ_TEST_REAL_OCR=1` включает эти проверки;
без неё часть проверок окружения может быть пропущена.

```bash
AZ_TEST_REAL_OCR=1 python -B -m unittest -v \
  test_medical_supplies_documents test_medical_supplies_ocr \
  test_medical_supplies_ocr_table test_medical_supplies_ocr_loss \
  test_medical_supplies_ocr_image test_medical_supplies_ocr_enrichment \
  test_medical_supplies_ocr_quality test_medical_supplies_ocr_automatic

python -B -m unittest \
  test_medical_supplies test_medical_supplies_import \
  test_medical_supplies_daily test_accounting_section test_section_navigation

python -B -m unittest test_nn_foundation
```

Общие регрессии и NN запускаются отдельными процессами, как в CI.
Браузерные проверки используют временную SQLite и локальный Flask:

```bash
export CHROMIUM_PATH="$(python -c 'from playwright.sync_api import sync_playwright; p=sync_playwright().start(); print(p.chromium.executable_path); p.stop()')"
python -B browser_medical_supplies_import.py
python -B browser_medical_supplies_daily.py
python -B browser_medical_supplies_documents.py
python -B browser_medical_supplies_ocr.py
python -B browser_medical_supplies_automatic.py
```

Последний сценарий проверяет частичный успех двухстраничного обновления,
повторную ошибку, запрет сохранения устаревшей формы, свежие реквизиты,
автокатегорию, сверку итога и сохранение черновика на 320/390/1365 px.
Скриншоты пишутся в `med-browser-artifacts` либо `MED_BROWSER_ARTIFACTS`.
Проверки прав, CSRF, конфликтов, ручных пустых значений, возможности повторить
временный сбой и неизменности оригинала/склада находятся в маршрутных тестах.

Итоговые числа проверок, результаты CI и применимость к реальным документам
фиксируются отдельно для точного HEAD. Этот файл не заявляет завершённую
приёмку, установленный выпуск или `PASS / CLOSE` независимого аудитора.

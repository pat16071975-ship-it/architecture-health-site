# ЗТЛ: заказы, оплаты и права

Начало с пустой базы. Excel не импортируется. Стиль base.html и общая section_navigation сохранены. Код не пишет в report_data, cash receipts, MIS, зарплатный реестр или медрасходку из операций ЗТЛ.

## Интерфейс

УЧЕТ → ЗТЛ: выбор месяцев с/по (один месяц — одинаковые значения); общий список / группировка внешний-внутренний / только внутренние / внешние / юридические лица / частные клиенты. Независимый фильтр неоплаченных. Итог лаборатории остаётся за весь выбранный период; над отфильтрованной таблицей свои количество, выставлено, оплачено и остаток, без распределения затрат на отфильтрованную группу.

Новый заказ: дата счёта, LAB- и ручной номер, тип, плательщик, пациент, заказчик, врач только внутреннего заказа, работа, описание, сумма, дни отсрочки. Справочники имеют поиск, выбор и добавление из формы заказа при наличии права catalog. Изменение имени справочника сохраняет ID и журнал; тип плательщика не меняется. Отсрочка от неизменяемой серверной даты создания. Номер уникален. Сумму нельзя уменьшить ниже зачтённых оплат; плательщика/тип оплаченного заказа нельзя менять до отмены ошибочной оплаты.

Отчёт по врачам: только внутренние заказы по дате счёта, количество и стоимость работ с деталями. Оплата не влияет, вычеты из оборота не выполняются.

## Оплата

Сначала плательщик и тип расчётов (внутренние/внешние), затем общий платёж от старых счетов к новым, весь долг, частичная сумма или конкретный заказ. Долг включает все месяцы. Превышение сохраняется авансом. Перед сохранением показаны распределение и аванс; подписанное подтверждение привязано к пользователю, сроку 30 минут и версии журнала. При изменении данных нужен новый просмотр. Повтор отправки не создаёт платёж.

Внутренний платёж: ФИО пациента, услуга лечения, общая сумма оплаты лечения и выделенная сумма ЗТЛ. Только последняя является деньгами этого регистра. Полная сумма оплаты лечения — контекст подтверждения, не повторная выручка. Не подключено автоматическое сопоставление Ident. Один исходный платёж с несколькими заказами вводится одной записью; ручные отдельные вводы оператор должен сверять с документом. Внутренние/внешние распределения изолированы, чтобы оплата лечения не закрывала внешний счёт.

Дата, сумма и способ обязательны. Документ PDF/PNG/JPEG до 1 МБ либо обязательное пояснение. Проверяется сигнатура содержимого; выдача только с accounting, attachment, nosniff, no-store. Документы хранятся BLOB в той же транзакции и резервируются вместе с БД. Нет публичных ссылок.

Аванс зачитывается явной кнопкой пользователем с правом payments; создание заказа не даёт orders-пользователю менять платежи. Зачёт по старым долгам, денежного потока не создаёт. Баланс: аванс минус незакрытые счета, плюс означает средства клиента. При ошибке платёж отменяется с причиной и историей, затем вводится правильный. Отмена записи — не реальный возврат денег. Возвраты денег не реализованы.

## Итоги

Заказы периода — по дате счёта. Оплаты этих заказов и долг — на момент формирования отчёта, включая оплаты позже месяца заказа.
- Теоретический результат = выставлено − затраты периода.
- Не оплачено = выставлено − распределённые действующие оплаты.
- Фактический результат = теоретический − не оплачено.
- Рентабельность = фактический / распределённые оплаты × 100%; при нуле оплат отсутствует.
- Денежный поток = действующие платежи ЗТЛ по дате поступления за период, включая авансы и оплаты старых счетов, без повторного зачёта авансов.

Затраты лаборатории и общеклинические расходы — отдельные суммы каждого месяца. ФОТ: зарплата и налоги каждого сотрудника, сумма автоматически. Право payroll позволяет добавить сотрудника непосредственно при начислении. Отдельное подтверждение полного ФОТ месяца обязательно; изменение начисления снимает подтверждение. Пустые затраты не ноль; прибыль и рентабельность отсутствуют до обеих статей и подтверждения ФОТ во всех месяцах. Известные затраты показаны отдельно.

## Права

Просмотр всего раздела и документов — accounting. Изменение дополнительно:
- ztl_orders: заказы, суммы, даты, отсрочки;
- ztl_catalog: справочники;
- ztl_payments: платежи, документы, авансы, отмена ошибочной записи;
- ztl_payroll: зарплата и налоги, сотрудник при начислении;
- ztl_lab_costs: затраты лаборатории;
- ztl_clinic_costs: общеклинические затраты.

Обычные администраторы получают права по действующему convention app.user_permissions, пользователям выдаются любые отдельные флаги существующей формой доступа. Новые права сами не выдаются обычным пользователям. Без accounting edit-флаг недостаточен. Все записи CSRF, журнал в той же транзакции. Заказы, карточки и затраты с version; распределения с global ledger stamp. Ошибка журнала откатывает изменение.

Медрасходка: medical_supplies_catalog / in / out / purchase. Прежний medical_supplies_edit сохраняется как явный полный доступ; чтобы ограничить такого пользователя, нужно снять прежний флаг и отметить нужные. Приход и расход сохраняются независимо: недоступное поле берётся с сервера, не из POST. Новая таблица coverage отличает незаполненную половину от реального нуля; старые строки без coverage считаются заполненными как раньше. Старые таблицы не переписываются. Неизвестный расход или приход блокирует полный остаток и заказ.

## Установка

Кандидат не устанавливает себя. Требуется отдельный guarded deploy после независимого аудита и разрешения владельца: backup БД/файлов, runtime-файлы, явный schema init, integrity/empty-table checks и health. Восемь новых таблиц: семь ztl_* и med_supply_coverage. Никаких seed/import/backfill, изменения пользовательских grants, синхронизаций и таймеров. Независимый аудит должен проверить exact HEAD, UI, матрицу прав, FIFO/авансы, помесячную полноту, сохранность остальных финансовых регистров.

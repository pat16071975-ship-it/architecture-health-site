# AZ BAZE — Администраторы (изолированная версия для просмотра)

Дата: 23.11.2026. Источник: прямые решения владельца, зафиксированные в AZ-HANDOVER-AZ-BAZE ч.27.

## Область

Один новый корневой раздел `/administrators/`: «Табель рабочего времени», «ФОТ админов», «Настройки». Нет связей с Финрезом, бухгалтерией, существующим ФОТ врачей, управленческим отчётом, МИС или сторонними сервисами. В настоящем PR только код; стабильная ветка, Production, БД и права действующих пользователей не изменяются.

## Рабочее поведение

- Табель: месяцы вперёд/назад и выбор месяца; ФИО и итог часов расположены рядом и закреплены. Календарные выходные и праздники выделены, но рабочий день может приходиться на любую дату. Для каждого нового дня показано «вых» без записи в БД; часы выбираются взамен.
- ФОТ: ставка в рублях за час; часы из табеля (без второго ввода); персональные премии для каждого сотрудника и месяца. Стандарты и конверсия: назначенная сумма × отработанные часы / 180. Категория, план, допначисления: фиксированные. Итого на руки — сумма без налогов и удержаний. Общий ФОТ — сумма итогов за выбранный месяц.
- Настройки: ФИО и ставка, сохранение ставок по месяцу действия, возможность сделать сотрудника неактивным без удаления истории.
- Закрытие месяца: сервер сохраняет неизменяемый снимок табеля, ставок, премий и ФОТ; после закрытия любые редактирования этого месяца возвращают 409. Повторное открытие только с отдельным правом; действия журналируются.
- Данные закрытого месяца читаются только из снимка, даже если после закрытия меняются имя или будущая ставка.
- GET не создаёт таблицы и не меняет данные. Неоткрытый месяц не имеет записанных «нулевых» часов.

## Права

| Ключ | Разрешение |
| --- | --- |
| `admins_view` | просмотр раздела |
| `admins_hours` | ввод/изменение часов |
| `admins_payroll` | ввод/изменение премий |
| `admins_settings` | ФИО, ставки, активность |
| `admins_close` | закрыть месяц |
| `admins_reopen` | повторно открыть месяц |

Права назначаются отдельно, не выдаются автоматически системному администратору. Владелец имеет доступ. Назначить `admins_reopen` вправе только владелец. Действия проверяются сервером, с CSRF на POST.

## Хранение

`az_admin_staff`, `az_admin_rates`, `az_admin_days`, `az_admin_bonuses`, `az_admin_months`, `az_admin_events` — полностью изолированные таблицы. Схема создаётся явной операцией `administrators.init_schema(conn)` на **отдельном согласованном контуре**, не через GET и не при регистрации приложения. Реквизиты и персональные данные в репозиторий не добавляются.

## Границы текущей проверки

В этой версии подсвечиваются установленные общероссийские праздничные даты; переносы рабочих/нерабочих дней по ежегодным постановлениям пока не включены в расчёт, потому что отдельная точная производственная календарная спецификация не утверждена. Никакого автоматического начисления налогов, расчётов фактических выплат или экспорта нет. В исходном PR не выполняется migration/deploy. Демонстрационный интерфейс и техпроверка не равны пользовательской приёмке или Production PASS.

## Исправления независимого FAIL / RETURN PR #252 (AZ-252-01…04)

- **AZ-252-01:** каждое POST-изменение табеля, премий и настроек содержит версию выбранного месяца; сравнение версии с текущей записью выполняется внутри `BEGIN IMMEDIATE`. Любое фактическое изменение атомарно повышает версию. Операции закрытия и повторного открытия также проверяют и повышают версию. Устаревшая форма отклоняется HTTP 409 без изменения БД и журнала; пропущенная/невалидная версия — HTTP 400. Месячная версия намеренно общая: после любого изменения в выбранном месяце открытую ранее форму нужно обновить.
- **AZ-252-02:** учётная запись с назначенным `admins_reopen` считается защищённой. Не владелец, даже имеющий системную роль администратора, не может открыть/сохранить её карточку или выдать новый временный пароль; маршруты возвращают 403 до записи и показа пароля. Назначение `admins_reopen` также доступно только владельцу.
- **AZ-252-03:** при изменении ставки за прошлый месяц прежняя дата будущего отключения сотрудника сохраняется. Изменение ставки не становится командой повторной активации в последующие месяцы.
- **AZ-252-04:** CI использует полный checkout, явное получение и проверку точного BASE, проверку HEAD и ancestry; скрипт `az-baze-auth/verify_administrators_scope.sh` завершается с ошибкой при недоступном объекте, пустом/невалидном diff или изменении файла вне строгого перечня PR. Есть negative-control запуск с заведомо отсутствующим BASE. Ошибка `git diff` не скрывается конструкцией `! ... | grep`.

Перед независимым re-audit требуются успешные CI на новом точном HEAD. Технический CI PASS не означает независимый audit PASS или разрешение на deploy. Draft, Production, БД и пользователи не меняются.

# AZ BAZE — Администраторы (изолированная версия для просмотра)

Дата: 23.11.2026. Источник: прямые решения владельца, зафиксированные в AZ-HANDOVER-AZ-BAZE ч.27.

## Область

Один новый корневой раздел `/administrators/`: «Табель рабочего времени», «ФОТ админов», «Настройки». Нет связей с Финрезом, бухгалтерией, существующим ФОТ врачей, управленческим отчётом, МИС или сторонними сервисами. В настоящем PR только код; стабильная ветка, Production, БД и права действующих пользователей не изменяются.

## Рабочее поведение

- Табель: месяцы вперёд/назад и выбор месяца; все календарные дни (до 31) и итоги помещаются по ширине таблицы на ПК без горизонтальной прокрутки. ФИО в табеле — фамилия и инициалы, полное имя продолжает храниться и редактироваться в настройках. Выходные и праздники подсвечены, но можно ввести часы на любую дату. Ввод свободный: пустая ячейка или 0 означает отсутствие работы, дробные часы допускаются до точности одной минуты. Часы **не записываются при вводе**: кнопка «Сохранить» под всем табелем фиксирует всю матрицу месяца одной атомарной операцией; после COMMIT появляется подтверждающее окно с названием месяца.
- ФОТ: ставка в рублях за час; часы из табеля (без второго ввода); персональные премии для каждого сотрудника и месяца. Стандарты и конверсия: назначенная сумма × отработанные часы / 180. Категория, план, допначисления: фиксированные. Итого на руки — сумма без налогов и удержаний. Общий ФОТ — сумма итогов за выбранный месяц.
- Настройки: ФИО и ставка, сохранение ставок по месяцу действия, возможность сделать сотрудника неактивным без удаления истории. Под формой — читаемый журнал изменений по всем месяцам: когда, кто, какого администратора, что изменил (часы, ставки, премии, закрытие месяца); по 100 событий на страницу с переходом к старшим событиям.
- Закрытие месяца: сервер сохраняет неизменяемый снимок табеля, ставок, премий и ФОТ; после закрытия любые редактирования этого месяца возвращают 409. Повторное открытие только с отдельным правом; действия журналируются.
- Данные закрытого месяца читаются только из снимка, даже если после закрытия меняются имя или будущая ставка.
- GET не создаёт таблицы и не меняет данные. Неоткрытый месяц не имеет записанных «нулевых» часов.

## Права

| Ключ | Разрешение |
| --- | --- |
| `admins_view` | просмотр раздела |
| `admins_hours` | ввод/изменение часов |
| `admins_payroll` | ввод/изменение премий |
| `admins_settings` | ФИО, ставки, активность |
| `admins_close` | закрыть месяц |
| `admins_reopen` | повторно открыть месяц |

Права назначаются отдельно, не выдаются автоматически системному администратору. Владелец имеет доступ. Назначить `admins_reopen` вправе только владелец. Действия проверяются сервером, с CSRF на POST.

## Хранение

`az_admin_staff`, `az_admin_rates`, `az_admin_days`, `az_admin_bonuses`, `az_admin_months`, `az_admin_events` — полностью изолированные таблицы. Схема создаётся явной операцией `administrators.init_schema(conn)` на **отдельном согласованном контуре**, не через GET и не при регистрации приложения. Реквизиты и персональные данные в репозиторий не добавляются.

## Границы текущей проверки

В этой версии подсвечиваются установленные общероссийские праздничные даты; переносы рабочих/нерабочих дней по ежегодным постановлениям пока не включены в расчёт, потому что отдельная точная производственная календарная спецификация не утверждена. Никакого автоматического начисления налогов, расчётов фактических выплат или экспорта нет. В исходном PR не выполняется migration/deploy. Демонстрационный интерфейс и техпроверка не равны пользовательской приёмке или Production PASS.

## Исправления независимого FAIL / RETURN PR #252 (AZ-252-01…04)

- **AZ-252-01:** каждое POST-изменение табеля, премий и настроек содержит версию выбранного месяца; сравнение версии с текущей записью выполняется внутри `BEGIN IMMEDIATE`. Любое фактическое изменение атомарно повышает версию. Операции закрытия и повторного открытия также проверяют и повышают версию. Устаревшая форма отклоняется HTTP 409 без изменения БД и журнала; пропущенная/невалидная версия — HTTP 400. Месячная версия намеренно общая: после любого изменения в выбранном месяце открытую ранее форму нужно обновить.
- **AZ-252-02:** учётная запись с назначенным `admins_reopen` считается защищённой. Не владелец, даже имеющий системную роль администратора, не может открыть/сохранить её карточку или выдать новый временный пароль; маршруты возвращают 403 до записи и показа пароля. Назначение `admins_reopen` также доступно только владельцу.
- **AZ-252-03:** при изменении ставки за прошлый месяц прежняя дата будущего отключения сотрудника сохраняется. Изменение ставки не становится командой повторной активации в последующие месяцы.
- **AZ-252-04:** CI использует полный checkout, явное получение и проверку точного BASE, проверку HEAD и ancestry; скрипт `az-baze-auth/verify_administrators_scope.sh` завершается с ошибкой при недоступном объекте, пустом/невалидном diff или изменении файла вне строгого перечня PR. Есть negative-control запуск с заведомо отсутствующим BASE. Ошибка `git diff` не скрывается конструкцией `! ... | grep`.

Перед независимым re-audit требуются успешные CI на новом точном HEAD. Технический CI PASS не означает независимый audit PASS или разрешение на deploy. Draft, Production, БД и пользователи не меняются.

## Повторный FAIL / RETURN: AZ-252-01 — наследование данных между месяцами

После первого исправления проверка `az_admin_months.version` защищала только изменения внутри выбранного месяца. Контрпример независимого аудита: пользователь открыл декабрьскую форму при унаследованной ставке 200 ₽/ч; изменение ставки в ноябре на 210 ₽/ч изменило декабрьскую сумму без инкремента версии декабря. Старая декабрьская форма могла вернуть 200 ₽/ч или подтвердить закрытие суммы 2 100 ₽, хотя пользователю до изменения показывали 2 000 ₽.

Исправление: **`month_view_revision(conn, month)`** вычисляет SHA-256 канонического содержимого фактически отображаемого месяца (`model`: текущая месячная версия, состояние закрытия, ФИО, активность, действующая ставка, часы, премии, суммы). Форма несёт отдельный `view_revision` вместе с прежней числовой `version`. На сервере оба значения проверяются **внутри того же `BEGIN IMMEDIATE`**, до любой записи, для операций часов, премий, ставок/настроек, закрытия и повторного открытия. Это учитывает изменения ставки и других отображаемых данных, пришедших из более ранних месяцев, включая месяц без собственной записи в `az_admin_months`. Состояние закрытого месяца считается по зафиксированному снимку, а не по позднейшим изменениям ставок.

При несовпадении — **HTTP 409**, данные и аудит остаются неизменными, требуется обновить страницу. При отсутствующем или недопустимом `view_revision` — HTTP 400. Дополнительных таблиц или массового инкремента версий будущих месяцев нет. Значения без изменений безопасно не блокируются: проверяется действительно видимое пользователю состояние.

Регрессии: (а) старая декабрьская форма ставки 200 ₽/ч после изменения ноябрьской ставки на 210 ₽/ч не сохраняется (409), фактическая ставка декабря остаётся 210; (б) старое подтверждение закрытия со снимком 2 000 ₽ не закрывает месяц после изменения наследуемой ставки, обновлённая форма показывает 2 100 ₽ и закрывает именно её (303); (в) устаревшие декабрьские формы часов/премий также отклоняются.

До нового независимого PASS / CLOSE, отдельного одобрения владельца и согласованного controlled-deploy PR остаётся **Draft / OPEN / UNMERGED**, без изменений рабочей БД и Production.

## Повторный конкурентный FAIL / RETURN: единый снимок страницы (AZ-252-01)

В HEAD `6f1200062abac288533a1e9aafd924e30bef4779` обнаружено окно между `model(conn, month)` и отдельным `month_view_revision(conn, month)` на GET. Если другой запрос меняет унаследованную ставку между ними, пользователь видит старый ФОТ 2 000 ₽, но форма подписана отпечатком нового ФОТ 2 100 ₽, после чего закрытие некорректно проходит с 303.

**Доработка:** `month_page_snapshot(conn, month)` открывает явную read-only SQLite транзакцию (`BEGIN`), получает из неё **один** `state, rows = model(conn, month)` и непосредственно из этих материализованных объектов вычисляет `month_view_revision_from_model(month, state, rows)` — без второго чтения БД. Снимок остаётся согласованным на протяжении всех SELECT внутри `model`, даже при параллельной записи в SQLite WAL. После чтения GET завершает read-транзакцию `rollback()` (никаких новых данных не сохраняется), а отрисовка использует те же state/rows/revision. Проверка при POST остаётся в `BEGIN IMMEDIATE` и пересчитывает актуальную версию под write-lock, возвращая 409 без изменения БД при конфликте.

**Независимое HTTP-воспроизведение для регрессии:** браузерный GET декабрьской формы после 10 часов по 200 ₽/ч, во время GET отдельный поток с отдельным соединением SQLite/Flask HTTP-POST меняет ноябрьскую ставку на 210 ₽/ч. Два контролируемых момента вмешательства: (1) после построения строк страницы непосредственно перед созданием токена; (2) между первым SELECT модели и последующими SELECT по ставкам. Требование: HTML по-прежнему содержит виденные 2 000 ₽ и token **старого снимка**, актуальная БД уже содержит 2 100 ₽, попытка закрыть из старой формы — 409 без каких-либо записей или журнала. Новый GET показывает 2 100 ₽. Существующие межмесячные и локальные регрессии сохраняются.

Никаких межмодульных связей, дополнительных DB миграций, расширения прав или Production действий в данной доработке нет. До независимого PASS/CLOSE и отдельного разрешения владельца PR остаётся Draft/OPEN/UNMERGED.

## Доработка по решению владельца 24.11.2026 — PR «Табель без Вых»

Только новый source-only PR после уже установленного PR #252. Никаких изменений схемы БД и миграций, прежние `az_admin_days`, `az_admin_events`, `az_admin_months`, ставки и премии сохраняются. Старый технический endpoint /administrators/hours не удалён для совместимости; новый интерфейс использует **POST /administrators/hours/batch** исключительно после явного нажатия «Сохранить».

При batch POST проверяются право `admins_hours`, CSRF, месяц, версия и единый view_revision из когерентного SQLite снимка (как после AZ-252-01). При `BEGIN IMMEDIATE` сверяются все видимые `staff_id` и дни месяца; лишние, пропущенные или повторяющиеся поля отклоняются. Вся новая матрица часов сначала валидируется целиком: дробные числа с точностью до минуты, 0/пустая ячейка = отсутствие записи. Только затем сохраняются отличия в `az_admin_days` и соответствующие неизменяемые события `az_admin_events`; версия месяца повышается один раз. Любая ошибка/гонка/закрытый месяц → rollback всех изменений и без окна «Сохранено».

Формат имени сокращён только при отрисовке табеля: `Петрова Анна Ивановна` → `Петрова А. И.`. В БД полные ФИО и архивные снимки не обрезаются. На ПК — все 31 дня вместе с ФИО и итогом в одной строке, `table-layout:fixed` и без горизонтальной полосы; на узком экране — те же поля в компактной сетке по 7 дней, без горизонтальной прокрутки. Пользователь видит знак «есть несохранённые изменения» и черновой итог, а сообщение «ТАБЕЛЬ СОХРАНЁН» появляется только после успешного POST/303 в **той же сессии**; прямой GET-параметр не может подделать подтверждение.

Раздел настроек содержит read-only пагинированный журнал уже существующей таблицы `az_admin_events`, в которой фиксируются действия старого и нового интерфейса. Изменения журнала в POST часов транзакционны с часами; GET не пишет в SQLite. ФОТ продолжает рассчитываться по сохранённым часам и прежним формулам. Отдельного разрешения на Product MERGE/DEPLOY без независимого аудита нет.

# ЗТЛ — восстановление подтверждённых строк оплат из первичных источников

Поручение владельца 25.11.2026: исправить отчёт ЗТЛ, включить исправленные
ноябрьские файлы и сохранённую историю. PR262 сохраняет исходные байты, но не
восстанавливает показатели. Соблюдены GEN-01…09, M-MONEY-01…05,
M-DATE-01…05, M-COVER-01, ранее утверждённый AZ-260-01.

Исправление: значение knownPaid, уже вычисляемое текущим парсером при
нераспределённой задолженности, больше не теряется. Для старых compact
источников допустима строго identity-matched выборка уже сохранённых
первичных paid lines (SHA, исходный интервал, import timestamp, количество
строк, оплаченный/выставленный итог); не используются рекламные метрики,
касса, ФИО пациентов, рекламная атрибуция. Ни рекламный отчёт, ни данные
поставщиков, ни прежние финансовые формулы не меняются.

Новая private CLI management_lab_recovery.py принимает проверенный архив
mis_archive_bundle (не HTTP, не передача данных). --verify не пишет БД.
--apply требует отдельного разрешения на выбор истории и существующей БД:
архивирует оригиналы прежним audited archive_bundle, проверяет readback,
затем отдельной транзакцией добавляет immutable ZTL selection в новую
management_lab_recovery_runs. Не вызывает штатный импорт, не изменяет
report_data, daily_uploads, service_payment_*, кассу, рекламу.
Повтор каталога не активирует старую версию и не обновляет её baseline.
AZ-267-02: новый immutable run дополняет активный набор по месяцам;
только перечисленные месяцы заменяются новым выбором. До публикации
всего run проверяется совместимость каждой пары с текущими дневными
данными; уменьшение набора ранее наблюдаемых дней запрещено без отдельного
решения. При отказе предыдущие selections сохраняются, как и архивные
оригиналы. GET выбирает latest accepted per month, не resurrects
superseded same-month run при утрате актуальности; другие месяцы остаются.
Если выбор не удался, сохранённые оригиналы остаются сохранёнными.

Пары выбираются только по явным monthly_candidates SHA из проверенного
manifest; пересчитываются по actual XLSX, не по цифрам из каталога.
Строгие стандартные колонки, invoice/date/group/service/qty/net multiset,
проверка суммы строк с итогом, наследование группы внутри счёта.
AZ-267-01: до архивации/выбора проверяются все четыре денежные колонки
(начальная задолженность + услуги − оплачено = конечная задолженность)
для строк, счета, пациента, исполнителя, итога «Услуги» и при наличии
общего итога/аванса. Поддержан стандартный styled IDENT layout с явными
уровнями provider/patient и плоский unstyled provider→invoice; неизвестная
иерархия отклоняется. Явные строки старой задолженности учитываются ровно
один раз, повторные подытоги сверяются с детализацией. Подтверждённые
отрицательные корректировки допустимы; необъяснённый остаток любого знака
отклоняется. Старый долг не распределяется по группам. Не
добавлять устаревшую альтернативную группировку. День с реальными услугами
не ЗТЛ является известным нулём; отсутствующий день не создаётся.
Уникальные счета, а не позиции; смешанный счёт учитывает только ЗТЛ строки.
Полная сумма оплат включая old debt НЕ устанавливается по совпадению
остатка или по кассе. Из архива восстанавливается knownPaid, не paid.
Наблюдаемые границы не доказывают полный календарный месяц.

Проекция full management GET read-only: активные источники остаются
основными; восстановленные свидетельства дополняют недостающие наблюдаемые
дни только без конфликтов с live (включая очищенный services layer).
Изменение источников в диапазоне инвалидирует старую recovery baseline.
Не активируются никакие другие бизнес-данные. Непересекающиеся полные
срезы остаются прежними. Для partial известной оплаты отдельная видимая
пометка «По строкам услуг», подсказка границ и неизвестной полной суммы.
Исторический fallback не режет месячный файл на дни, не суммирует с
пересекающимся active snapshot, требует источник каждого выбранного месяца.
Средний чек по-прежнему рассчитывается только из полной оплаты при полной
доказанной совокупности заказов; partial не выдаётся за этот показатель.
Compact dashboard без изменений.

PR262 runtime до этого мог оставаться не установлен. Будущая установка
должна учитывать физическую исходную версию и сохранить PR264 OCR.
Частные данные/архивы не добавляются в GitHub или CI, синтетические тесты
отдельно. Нельзя обещать исторический перенос без согласованного безопасного
канала передачи. Никакой ручной файловый путь не навязывается владельцу.

## Исправление физической приёмки PR267

По скриншоту владельца 25.11: убрать добавленную техническую подпись из денежной ячейки, вернуть две числовые строки, прежнюю ширину и высоту. Не прятать существующую прокрутку CSS: устранить причину расширения, проверить на 11 колонках desktop 1818px и прежних 1365/390px. Ограничение полноты — только в уже существующей подсказке. Не менять цвета, формулы, даты и прочие строки.

При явно принятом восстановлении исторической пары, проверенном сервером на актуальность, её knownPaid может заменить устаревший частичный knownPaid только для ровно того же интервала. Полные active paid сохраняют приоритет. Иная/неоднозначная граница не заменяет частичную сумму; нет суммирования перекрытий. Полная оплата и avg остаются неизвестны без прежнего доказательства. Для физического исправления суммы необходимо установить фактический активный source SHA и применить проверенный оригинал отдельным разрешённым способом; этот PR не переносит/активирует архив и не меняет БД.

# AZ BAZE — Медрасходка → Входящие документы

**Дата:** 24.11.2026  
**Статус:** Draft SOURCE-ONLY. Требует независимого READ-ONLY аудита и отдельного разрешения на MERGE / controlled Production release.

## Решение владельца

Создать внутри Медрасходки универсальную форму приёма разнообразных входящих документов (УПД, накладные, счета, акты, чеки, договоры и др.). В будущем добавлять специальные формы разбора на базе одного защищённого реестра оригиналов. Пример из обсуждения: УПД «Комус» от 20.11.2026. Пример **не загружается автоматически** в продукт.

## Что реализовано

- Кнопка «Входящие документы» в трёх вариантах Медрасходки: обычный месячный, дневной с папками, Excel-остатки.
- Отдельная страница \`/accounting/medical-supplies/incoming/\` с формой загрузки оригинала, указанием типа, контрагента, даты, номера, комментария.
- Поддержка PDF, JPG/PNG/WEBP/TIFF/BMP/HEIC/HEIF, Word DOC/DOCX, Excel XLS/XLSX, ODT/ODS, CSV/TXT/XML/JSON, RTF и ZIP. Максимум **20 МБ** на один документ. Сигнатуры файлов проверяются на сервере; ZIP проверяется на формат и ограниченные размеры. Нельзя загружать HTML, исполняемые программы или выдавать загруженный файл как HTML страницы.
- Исходные байты сохраняются **неизменными** в защищённой базе SQLite AZ BAZE; SHA-256 предотвращает повторную загрузку тех же байтов, даже если переименовали файл. Запись оригинала, метаданных и события истории выполняется в одной транзакции.
- Статусы **«На разбор» (по умолчанию)**, «В работе», «Разобран». Сохранение статуса НЕ создаёт прихода, склада, услуги, финансового документа или проводки.
- Поиск по контрагенту, номеру, имени файла и комментарию (включая кириллицу); фильтр по типу и статусу; пагинация по 50 записей. Карточка с чтением, ручным редактированием реквизитов и проверкой версии при конкурентных действиях.
- Показ оригинального PDF и пассивных изображений в браузере (со строгими заголовками безопасности); остальные форматы скачиваются как **attachment**, не исполняются и не открываются как HTML. Есть скачивание любого оригинала.
- События загрузки/разбора содержат только реквизиты, автора и время, **не содержат байтов исходного документа**. Исходный файл невозможно изменить через карточку; удаление не предоставляется (для сохранения аудита).
- Для дальнейших типов документов предусмотрено поле \`fields_json\` (начально \`{}\`): будущие специализированные формы смогут хранить результаты разбора, не смешивая первичный оригинал с документом учёта.

## Доступ

- **Просмотр и скачивание** — существующее \`accounting\` (УЧЁТ); анонимный доступ и сотрудники без УЧЁТ получают redirect/403.
- **Загрузка, изменение карточки и статуса** — отдельное право \`medical_supplies_documents_manage\` или уже действующее общее \`medical_supplies_edit\`. Owner / администратор сохраняет существующую модель доступа.
- CSRF обязателен для POST. Подмена типа файла, неправильный размер, неверные версии, необъявленные статусы, неподходящий формат и имитация Office-архива отклоняются.

## База и установочная граница

Новые **2 таблицы и 2 индекса**, без изменения существующих таблиц/записей:
- \`med_supply_documents\`: SHA, реквизиты, статус, версия, оригинальный BLOB, дата/автор, служебные JSON поля.
- \`med_supply_document_events\`: аудит загрузки/изменения карточки.

Schema-only \`init_schema()\` вызывается при **явной** установке схемы (\`app.init_db_file\` для новой БД / отдельная разрешённая миграция в Production). **GET не создаёт таблицы.** Если на действующем сервере схема не установлена, новая страница возвращает 503 с понятным текстом; нельзя заранее опубликовать только интерфейс без миграции.

При controlled Production release необходимы: read-only сверка действующего runtime и БД, резервная копия SQLite, idempotent добавление только этих 2 таблиц + 2 индексов, сохранность прежних объектов/строк, проверка доступа и реальная браузерная приёмка. До такого релиза ничего не устанавливать.

## Что НЕ делается

Автоматическое OCR, разбор УПД по позициям, сопоставление с материалами склада, отнесение кофе/канцелярии на медрасходы, подтверждение поставщика, проведение приходов/расходов, редактирование исторических stock imports, создание оплат, бухгалтерских проводок и обновление основных финансовых отчётов.

Это отдельные будущие формы и задачи, **только после решения владельца**, с подтверждением перед переносом в склад.

## Техническая проверка

\`test_medical_supplies_documents.py\`: SQLite/API регрессии точности оригинальных байтов и SHA, дублей, PDF/Excel/Office/текста, невалидных подписей, CSRF, прав, версионного конфликта, аудита, неизменности склада, no-write GET и безопасной выдачи файлов.

\`browser_medical_supplies_documents.py\`: Playwright Chromium, desktop 1365px и mobile 390px, навигация из Медрасходки, загрузка PDF, карточка, скачивание, статус, дубли, поиск и просмотрная роль.

Существующая профильная \`az-medical-supplies.yml\` дополнена новыми тестами; старые backend/browser тесты операций Медрасходки остаются активны.

**Аудит должен отдельно проверить право \`accounting\` на доступ к документам, CSRF, закачку 20 МБ, безопасность архивов и MIME, отсутствие записей при GET, отсутствие складских изменений и явность установки новых таблиц.**

# Порядок плашек разделов

## Как настроить

«Настройка клиник» → «Порядок плашек разделов». Выберите меню, переместите плашки кнопками ↑/↓ и нажмите «Сохранить порядок». Созданные настройки действуют для всех сотрудников этой установки AZ-BAZE, на компьютере и телефоне. Меняется порядок отображения доступных плашек, а не права доступа. Кнопка «Вернуть исходный порядок» действует только на выбранное меню. При уходе с несохранёнными изменениями браузер предупреждает.

Настраиваются: главное меню, «Отчёты», «УЧЕТ», «УЧЕТ → ЗТЛ», «УЧЕТ → Медрасходка», «Доступы и контакты», «Контроль», вкладки «Контроль → ЗТЛ», меню «Варикоза нет - KZ». Отдельные записи в справочниках, папки базы знаний, опросы и формы загрузки не являются меню разделов и этой настройкой не сортируются. На странице «Контроль» пока одна плашка; стрелки недоступны, пока не появятся другие.

Настройка общая для текущей установки, не персональная и не отдельная на каждый ID клиники: действующее главное меню не имеет переключателя активной клиники. Изменять порядок может владелец с действующим правом `structure_manage`; обычным администраторам эта возможность не предоставляется. Это также сохраняет изоляцию частного раздела НН. Строки журнала для главного меню и меню НН доступны только владельцу по существующему правилу `nn_%`.

## Архитектура и сохранность

- `menu_order.py` содержит каталог стабильных ID и неизменяемых адресов. Клиент отправляет только перестановку ID одного выбранного меню. Пропуски, повторы, посторонние ID и устаревший каталог отклоняются.
- Настройка хранится в `navigation_order`, одна строка на меню: JSON порядка, версия, автор и время. `null` означает исходный порядок; версия при сбросе сохраняется и увеличивается, чтобы старая форма не могла перезаписать новый результат.
- POST защищён действующими авторизацией и CSRF. `BEGIN IMMEDIATE`, проверка версии, запись порядка и журнала `audit_log` входят в одну транзакцию. Ошибка журнала откатывает весь результат. Повтор неизменённого текущего порядка ничего не пишет.
- GET ничего не создаёт и не обновляет, включая первоначальную загрузку настроек. При отсутствии таблицы прежние меню работают как раньше, настройки показывают недоступность сохранения.
- Flask выполняет новый обработчик после действующих обработчиков фильтрации прав и добавления плашек. Переставляются только исходные HTML-фрагменты ссылок внутри конкретных контейнеров меню. Ссылки, параметры периода, классы, подписи актуальности, обработчики и вложенные элементы не переписываются. Недоступная плашка не создаётся.
- Без сохранённой настройки HTML возвращается неизменным. Сброс восстанавливает действующий исходный порядок. Новые зарегистрированные ID следуют после сохранённых; удалённые ID игнорируются. Неизвестные расширения и прочая разметка не удаляются.
- Порядок не вмешивается в расчёты отчётов, заказы, склад, ФОТ, платежи и права. `server.py` не изменяется; рабочая регистрация `knowledge_catalog` остаётся на месте.
- Для нового меню/плашки разработчик добавляет стабильный ID в каталог, связывает точный контейнер и дополняет проверку соответствия реальному меню.

## Подготовка и проверка

Перед установкой нужна явная подготовка одной пустой таблицы через `menu_order.init_schema(conn)` внутри транзакции установщика. Подготовка не выполняется при импорте модуля, запуске приложения или GET. Старые строки данных не переносятся. Production — только после независимого аудита и разрешения владельца.

`test_menu_order.py` использует настоящий `server`, временную БД и синтетических пользователей. Проверяет все меню, права и изоляцию НН, CSRF, версии, сброс, повторный запрос, откат журнала, неизменность прочих таблиц, отсутствие записей при GET, повреждённую настройку и старые ссылки с периодами.

`browser_menu_order.py` проходит обычный вход с главной, меняет порядок во всех девяти меню кнопками, сохраняет и перезагружает, проверяет сотрудника с ограниченными правами, конфликт двух окон и сброс. Размеры 1365/390 px. Браузер запускается в CI на точном HEAD; проверка не пропускается при невозможности локального запуска Chromium.

# Медрасходка: сохранение строк и полных названий после OCR

Статус: DRAFT / SOURCE-ONLY. Пользовательская приёмка установленного PR271
возвращена: распознанный текст содержит позиции, которых нет в таблице,
а часть названий обрезана. Этот пакет пока не закрывает приёмку документа.

База: `9394e6a304fd1f6763e1b1044845134cdc431009`.

## Исправления в исходниках

- Начало многострочного названия отделяется от шапки до появления количества.
- Переносы остаются внутри товарного блока, ограниченного печатным номером.
- Доказанные товарные строки с неизвестным количеством сохраняются без догадок.
- Центрированный заголовок не задаёт произвольный отступ, отрезающий название.
- Продолжение артикула не мешает присоединению продолжения названия.
- Длинная шапка УПД, индексы колонок, «Цена (тариф)» и перенос подписей денежных
  полей обрабатываются без создания лишних колонок и фиктивного товара.
- Поле названия увеличивается по содержимому при показе, вводе и смене ширины.

Версия извлечения повышена до 3. Исходные words/lines, их идентификаторы,
пользовательские rows, реквизиты, checked/no_items и PDF сохраняются.
Runtime меняется только в medical_supplies_ocr.py и его шаблоне.
Маршруты, права, бизнес-проводки и схема БД не меняются.

## Проверки

Восемь новых структурных регрессий не содержат частных исходников.
Локальный профиль incoming/OCR: 60 PASS, 2 OCR environment SKIP, 0 FAIL.
Два настоящих OCR-теста остаются обязательными в профильном CI.
Браузер: семь размеров экрана; дополнительно длинные названия на 1365/390,
ввод, добавление строки и изменение ширины без потери текста или записи в БД.

## Незавершённая проверка

Сохранённый разбор реального документа на сервере ещё не получен. Синтетические
регрессии и другой ранее загруженный пример УПД его не заменяют.
Страница-продолжение без повторной шапки пока не получает контекст предыдущей;
название, пересекающее границу страниц, также требует отдельного исправления.
Сохранённые rows продолжают иметь приоритет над candidates: удалять их
автоматически нельзя, поскольку они могут содержать пользовательские правки.
До сверки всех позиций текущего документа выпуск не предлагается.

## Чтение фактического состояния

diagnose_medical_ocr_rows.py читает пять разрешённых колонок одного документа
через mode=ro/query_only с дополнительным SQLite authorizer. Оригинальные
байты, другие документы, каталоги, реквизиты и комментарии не выводятся.
Исполняются только два проверенных модуля установленного PR271; app/server
не загружаются, OCR не запускается, запись и сеть отсутствуют.
--all-pages включает все сохранённые страницы, --compact выводит обратимо
сжатый JSON в stdout. Данные возвращаются в рабочий чат; в репозиторий и CI
не помещаются. Диагностика не является установкой исправления.

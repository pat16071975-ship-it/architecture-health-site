# ЗТЛ в Управленческом отчёте: оплаты и услуги

24.11.2026 владелец подтвердил принцип: выручка лаборатории в одной строке,
верхняя цифра — оплаты IDENT, нижняя — услуги, независимо от исполнителя.
Рекламный отчёт и остальные отчёты не меняются.

## Источники

* Оплаты: исходный новый Excel «Выручка по направлениям (новый оплаты)»,
  графа «Оплачено» детальных строк с группой услуг. Группа — компонент пути
  «Зуботехническая лаборатория», в том числе подтверждённый вариант
  «Функциональная стоматология / Зуботехническая лаборатория (клиника)».
  Не классифицировать по фамилии, по подстроке в названии услуги или по кассе.
  Сумма строк сверяется в копейках с итогом каждого исполнителя и общим
  итогом нового отчёта. Неразнесённая оплата старой задолженности не
  приписывается группе: неизвестный результат не равен нулю.
* При новой загрузке агрегат management_lab_v1 сохраняется в том же
  compact snapshot/period, что и исходные оплаты; schema version и все
  старые поля сохраняются. Прежний compact не обогащается самопроизвольно.
  Если старый период загрузят повторно и новая детализация изменит payload,
  действует существующая проверка конфликта и явный выбор при замене.
* Услуги: оригинальные normalized_json / items старого экспорта «Выручка
  по направлениям», по фактическим загруженным датам; retail_items не
  включаются. Количество — уникальные номера счетов внутри даты счета,
  независимо от исполнителя; несколько строк одного счета не увеличивают
  число заказов. Без номера у лабораторной услуги количество неизвестно.
  Завершённые приёмы и очищенная services layer не являются нулевой услугой.
* Средний чек = подтверждённые оплаты / подтверждённое полное количество
  счетов ЗТЛ за те же границы, только при положительном знаменателе.
  Наличие хотя бы одной даты в каждом месяце НЕ подтверждает количество
  счетов за весь период. При неполноте знаменателя средний чек — прочерк.

## Периоды и границы

Используются границы выбранной колонки, как для врачей. Для оплат — точный
интервал или непрерывная неперекрывающаяся цепочка исходных интервалов.
Явный период имеет приоритет над срезом тех же границ. Более длинный или
соседний интервал не делится/не подставляется. Для услуг суммируются только
загруженные дни внутри границ, с источником в каждом месяце; подсказка
явно указывает охват загруженных дней. Услуги и количество счетов помечены
«по загруженным датам»; неполный счётчик не используется как знаменатель
среднего чека. При неизвестном источнике — прочерк, не старые кассовые
значения. Цвет ячейки определяется оплатами.

### AZ-260-01 — доказательство охвата знаменателя

Текущий сохранённый источник содержит фактические даты услуг, но не
независимое подтверждение полного интервала, включая дни без операций.
Поэтому с имеющимися доказательствами полное покрытие можно установить,
только если для каждой календарной даты выбранного интервала уже имеется
валидная запись источника с известным количеством счетов и суммой услуг.
День с реальными строками других групп и без ЗТЛ — доказанный ноль счетов;
отсутствующая дата или очищенный/повреждённый источник — неизвестность.
Не создавать записи ради среднего чека и не считать выходные автоматически
нулём. Это консервативное ограничение текущего контракта, а не требование
ежедневной загрузки в нерабочие дни: при корректной выгрузке без строк в
отдельные дни средний чек останется неизвестным до появления независимого
подтверждения охвата. Отдельный механизм такого подтверждения не вводится
данной узкой правкой. Проверки AZ-260-01 охватывают крайние и внутренние
пропуски, неполный/полный месяц, квартал, полугодие, обычный и високосный
год, дубли, истинный ноль, неизвестный номер счёта, отрицательные оплаты
и покрытие оплат точным периодом/непересекающейся цепочкой.

Новые поля только в полном management API, не в dashboard projection.
GET не меняет БД. Существующие doctor totals, cashTotal, labRevenue/factLab
в сохранённых payload, рекламные данные, provider registry, старые ручные
поля и все другие расчёты остаются прежними. Новая строка ЗТЛ не прибавляется
к общему «Факту» и не меняет ранее утверждённые врачебные суммы. Это отдельный
аналитический разрез, не слагаемое суммы по исполнителям.

Исторические платежи без сохранённой групповой детализации остаются
неизвестными до отдельной санкционированной сверки/обогащения источника.
Ранее названные 946730 / 511140 / 9500 ₽ не зашиваются в код и не являются
доказательством текущего содержимого БД. Никакого backfill, миграции,
изменения БД или выпуска этим PR.

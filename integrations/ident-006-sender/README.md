Пароль SQL вводится один раз непосредственно в локальном интерактивном консоле после явной provisioning-команды, через SecureString (без эха). HTTP bearer token генерируется криптографически случайно на компьютере, 32 random bytes -> 64 lowercase hex ASCII. Только SHA-256 токена выводится для регистрации на сервере. Ни пароль, ни raw token не передаются через аргументы, environment, Git, чат, URL, log или plaintext файл. DPAPI LocalMachine + отдельный protected ACL, entropy = hash полной конфигурации + отдельное назначение (password, token, packet sequence, ack sequence). Это машинная, не пользовательская DPAPI: администратор и виртуальная учётная запись могут использовать ciphertext, другой локальный пользователь, получивший ciphertext, теоретически тоже сможет его расшифровать на том же компьютере; ACL — обязательная граница. Не защищает от администратора, malware внутри trusted account, memory dump, полного компромета Windows. HTTPS token кратковременно находится в HTTP header в памяти; SQL пароль расшифровывается в память и передаётся SqlCredential как SecureString. Диск/резервные копии и старый исходный plaintext пакет требуют отдельной проверки защиты (BitLocker, policy); исходный файл не удаляется без разрешения. Изменение config/pin/token ломает DPAPI binding и требует отдельной согласованной процедуры rekey/migration, а не ручной правки файла. В этой дельте нет rotation/reset/uninstall или переноса DPAPI между машинами.

## Очередь и восстановление

В journal каждый packet-N.bin — DPAPI-encrypted exact bytes, каждый ack-N.bin — DPAPI-encrypted полный ответ. N постоянный 16-значный sequence начиная с 1. Проверка первого SHA, всех полей, UUID, strict JSON keys, точности decimal через BigInteger, полного периода и schema. Перед публикацией проверка capacity + reserve. FileMode.CreateNew, WriteThrough, Flush(true), MoveFileEx WRITE_THROUGH без replacement. Нет сетевой отправки до локальной публикации. Непубликованный encrypted .tmp не считается пакетом, никогда не отправляется, сохраняется. Локальные files/receipts не удаляются автоматически. При запуске восстановление последовательности из immutable journal, обнаружение дыр/изменений, привязка к first packet, один неподтверждённый пакет. Хранение всей истории ограничено max_history_bytes (16 MiB..8 GiB) и резервом free space; при заполнении стоп нового сбора, попытка доставки pending сохраняется. Retention/backup/monitoring отдельно. Нет гарантии защиты от повреждения диска или намеренного rollback администратором: server prefix guard обнаруживает сервер впереди/позади local acknowledged history; конфликт требует reconciliation.

HTTPS origin строго фиксированный HTTPS DNS host port 443 без path/query/userinfo/redirect. TLS1.2/1.3, default Windows chain/hostname validation, no proxy/cookie/redirect/decompression, bounded response, request timeout, no trust bypass. GET status: strict identity, shadow_only, contiguous accepted_batches=max_sequence. POST exact raw bytes, token per request. ACK обязан совпасть по contract, dataset, source, stream, batch, sequence, SHA-256 и статусу accepted/already_accepted; валидный ACK сохраняется до продвижения sequence. Потерянный ACK после commit — повтор тех же байтов (server idempotent). 429/5xx/network/timeout — retry с backoff 30..900s; 401/403/409/422/invalid receipt/permanent contract — blocked, ручная проверка и restart. SQL auth failure blocks; прочие SQL errors retry, READ-ONLY guard failure blocks. Никаких подстановок нулей при ошибке запроса. Отсутствующие строки успешного SQL полного окна — подтверждённый ноль.

Один pending на пилоте: при сетевой ошибке без pending можно собрать и зафиксировать один пакет; пока он не принят, новые запросы не выполняются. После восстановления догружаются все пропущенные календарные даты contiguous windows <=31 дня. Rolling lookback 1..31, cadence 15..1440 min (пример 30 min / 31 days, не установленный график). Часовой пояс IANA source, Windows mapping, UTC observation. При большой задержке догрузка чанками, затем очередное rolling окно. Поздние изменения исторических записей старше rolling window требуют отдельного backfill; это не доказательство полноты кассовой/paid-services отчётности. Текущий день не считается закрытым. Не суммировать уникальных плативших по дням за месяц. Автоматическая передача после отключения электропитания зависит от Windows загрузки, BIOS AC power restore, сети, IDENT и receiver. Настройка BIOS и полный тест reboot/power cycle реального EX-18-4 отдельно.

# IDENT-006A — серверный приёмник AZ BAZE, SOURCE-ONLY

Назначение: первая серверная половина автоматической интеграции IDENT, отдельно от действующего импорта Excel и действующей финансовой отчётности AZ BAZE. Исходный срез AZ BAZE: 9394e6a304fd1f6763e1b1044845134cdc431009. Проверены server.py (Flask, регистрация существующих маршрутов), app.py (SQLite, браузерные права), report_storage.py (финансовые проекции) и mis_source_archive.py (архив исходных файлов). Их код, schema, auth.db, Nginx, права браузерных пользователей, UI и расчёты не изменяются.

## Границы

Отдельный Python WSGI-компонент, совместимый с используемым в AZ BAZE Gunicorn. Отдельная БД на сервере AZ BAZE — теневая (shadow), не в public web-root, не auth.db. Установка, запуск, создание реального токена, реальной БД и открытие маршрутов на Production требуют отдельного согласования. Не содержит Windows-отправителя, службы, автоматической отправки, интеграции в отчёты, персональных данных или реальных конфигураций. Не подключается к IDENT. В этой дельте только source и синтетический CI.

Пакет payments_daily_v1 — суммы записей PaymentsIn всей разрешённой базы за локальные календарные даты. Не эквивалент подтверждённой кассе, выручке, оплаченной услуге, оплате ЗТЛ или определённому филиалу. До сверки не подключать к cashTotal, factMedicine, factLab, paid services и любому активному отчёту. Не суммировать дневное число уникальных плативших пациентов как уникальное число за месяц.

## Код

- gateway.py — отдельный аутентифицированный WSGI API, регистрация источника через частную конфигурацию, отдельное хранилище, ACK, диагностика.
- core/receiver.py и core/sql/payments_daily_v1.sql — неизменённые Git blobs из прошедшего независимый аудит IDENT-004-TLS HEAD 7ffc65174a408a75afc237247045008e7bab51dd. В gateway переиспользуются только типы, валидатор и определения таблиц batches/daily. Новая реализация хранилища имеет отдельный application_id IB6A, явный synchronous=FULL, привязку организации и ограничение ёмкости. Старый offline store не принимается за новый.
- tests/test_gateway.py — синтетические unit/integration тесты контракта, аутентификации, отказов, параллельности, атомарности и восстановления.
- tests/smoke_gunicorn.py — фактический Gunicorn HTTP по локальному Unix socket; не проверка внешнего TLS.
- requirements.txt — Gunicorn той же версии, что в исходном AZ BAZE. Для реальной поставки зафиксировать и проверить также транзитивные зависимости и системный Python/SQLite, отдельный venv или проверенный runtime.

## Регистрация источника и безопасность

Одна инсталляция приёмника обслуживает ровно одну утверждённую организацию, source_id, stream_id и source_timezone; новый источник — отдельная конфигурация/БД/экземпляр. Привязка сохраняется и проверяется в самой БД, не выбирается из входного JSON, HTTP path, cookie или заголовка организации. Смена источника, потока, организации или timezone не переиспользует старую БД. Реальные source_id и stream_id следует извлечь из уже созданного первого локального пакета на EX-18-4 (не из диагностических случайных ID). Пока не регистрируем их.

Вне Git оператор создаёт секрет из 32 криптографически случайных байт, кодирует его 64 строчными hex-символами. Сервер хранит только SHA-256 этого ASCII-токена; клиент предъявляет Authorization: Bearer с исходными 64 hex-символами. Сравнение хеша константное. Пароль SQL не нужен серверному приёмнику и не пересылается. Реальные токены не входят в команды для чата, URL, логи и репозиторий. Смена/отзыв токена: остановить/перезапустить отдельный сервис с новым verifier, отдельно обновить защищённое хранилище отправителя. Нет UI для регистрации, нет публичного endpoint enrolment, нет выдачи токенов по сети.

Конфигурация JSON в отдельном абсолютном пути, с ровно следующими полями:

    organization_id: канонический UUID зарегистрированной организации
    source_id: канонический UUID источника
    stream_id: канонический UUID потока
    source_timezone: IANA timezone
    token_sha256: 64 строчных hex-символа
    max_store_bytes: лимит размера SQLite, целое число от 16 МиБ до 8 ГиБ
    min_free_bytes: резерв свободного места, целое число от 16 МиБ до 8 ГиБ

Лимиты выбираются при реальной конфигурации, это пилотные технические границы. Ограничение SQLite max_page_count не ограничивает суммарный объём rollback journal, резервных копий и других процессов. Проверка свободного места — дополнительная ранняя остановка, не гарантия отсутствия ENOSPC. До эксплуатации проверить отдельный volume/квоту, мониторинг и резерв места. При заполнении возвращается 503, не удаляем старые пакеты и не затираем историю. Политика срока хранения пока не утверждена.

Отдельная непривилегированная Linux-учётная запись; private state mode 0700, база 0600, config 0600 или root-owned 0640 для выделенной группы. Отказ при запуске root, небезопасных предках/символических ссылках/правах, посторонней БД, чужой привязке. Известный store и rollback journal проверяются до RW открытия. Recovery при старте разрешено только для собственного формата БД. Инициализация отдельной командой, транзакционная схема, fsync, атомарная no-clobber публикация; не перезаписывать чужие файлы. При прерывании между hardlink и unlink может остаться временная ссылка: проверка nlink остановит запуск; операторская проверка и восстановление требуется отдельно. Нет защиты от root, компрометации ОС или процессов той же доверенной учётной записи. Продакшен должен использовать проверенное приватное хранилище/дисковое шифрование и закрытые резервные копии; приложение само не шифрует SQLite.

## API (пока не опубликован)

Только за HTTPS reverse proxy, отдельный Unix socket, не TCP-порт. Nginx заменяет X-Forwarded-Proto на https; WSGI должен определить схему https. Заголовок не является аутентификацией. Доступ к сокету только доверенному прокси и сервису. Нельзя запускать gateway на доступном HTTP listener.

POST /api/ident-bridge/v1/batches — Content-Type application/json (допустим utf-8), Content-Length 1..524288, без Content-Encoding/Transfer-Encoding на участке прокси—приёмник. Не передавать URL query. Сначала проверяется token, затем ограничение и чтение тела. Валидация целиком, включая UUID, типы, точные decimal-строки, покрытие 1..31 день, отпечаток запроса, схема, даты, дубликаты JSON, отсутствие лишних полей. observed_at не более чем на 5 минут в будущем от серверного времени (требование синхронизации часов). Не принимает персональные строки.

HTTP 200 только после commit полного пакета или подтверждения ранее записанных тех же байтов:

    contract_version=1, dataset, source_id, stream_id,
    batch_id, sequence, payload_sha256, accepted_at,
    status=accepted | already_accepted

ACK при повторе возвращает исходный accepted_at. Клиент обязан проверять все идентификаторы, sequence, hash, dataset и status; одного HTTP 200 недостаточно. Архивируются исходные байты BLOB, SHA-256 и проекция дневных строк в одной транзакции BEGIN IMMEDIATE с FULL synchronous. Новый sequence заменяет дневные значения только своего окна. Старое непересекающееся окно допустимо; устаревшее пересекающееся окно отвергается целиком. Равный sequence с другими байтами, UUID batch с новым sequence, смена схемы: конфликт. Дубликат того же содержимого не увеличивает показатели. Ошибка любого шага/SQLITE_FULL/сбой записи — нет ACK. При crash незавершённая транзакция откатывается SQLite при следующем открытии. Повтор отправителем именно тех же байтов восстанавливает ACK после потери ответа.

HTTP 401 — неверный/отсутствующий machine token; 400/411/413/415 — некорректный транспорт; 422 — невалидный пакет; 409 — конфликт identity версии/пересечения/схемы; 503 — временная недоступность или лимит. Ошибки не содержат исходных данных, credentials или raw SQL/traceback. Не считать 4xx успешной передачей; не повторять конфликт бесконечно. 503/сетевые ошибки — retry с backoff. Не удалять локальный файл до валидного ACK.

GET /api/ident-bridge/v1/status — тот же machine token; количество принятых пакетов, max_sequence, последний accepted_at, крайние даты наблюдения, mode=shadow_only. Не выдаёт суммы или пакеты. Нет публичной health страницы, download, чтения financial rows, browser session bypass. Последний accepted_at — не доказательство закрытия дня и не heartbeat при отсутствии отправки.

## План отдельной установки (НЕ выполнен)

1. Согласовать серверный контур (отдельный приватный state, отдельный непривилегированный пользователь), проверенный runtime, provisioning config/token, права, резерв и архивирование. Подтвердить действующий HTTPS-host AZ BAZE без изменения текущих routes. Сервис только на private Unix socket, права на него — сервис + reverse proxy, без world access. Runtime и исходники read-only для пользователя сервиса.
2. Только после одобрения явная инициализация: IDENT_RECEIVER_CONFIG и IDENT_RECEIVER_STATE_DIR указывают проверенные абсолютные пути. Запуск python3 gateway.py init под сервисной учётной записью. CLI status под той же учётной записью. Не создавать state внутри /var/www, каталога установки, текущей auth.db или существующего отчётного хранилища.
3. Gunicorn factory gateway:create_app(), отдельный процесс, private Unix socket, ограниченные workers/threads/timeouts, безопасная umask. Настроить systemd auto-start и restart, права на socket без доступа к state. Приёмник не пишет в существующую AZ BAZE. Точный unit/installer и маршруты подготовить и проверить отдельно.
4. Nginx: два exact location для указанных paths, только HTTPS, upstream private Unix socket. Заменять X-Forwarded-Proto=https, удалять конкурирующие X-Forwarded-SSL/X-Forwarded-Protocol и недоверенные forwarding headers, не пропускать токен в журнал. Proxy request buffering, client_max_body_size 512k, ограничение частоты и одновременных подключений, таймауты; не публиковать остальные пути, не использовать редирект с Bearer. Физическая проверка TLS, route isolation, HTTPS и размера до отправки реальных данных. Gunicorn Unix smoke доказывает работу схемы/авторизации по локальному сокету, но не конфигурацию внешнего Nginx и сертификата.
5. Синтетический контроль на отдельной БД, точная проверка привязки и отказов, реальный первый пакет только по отдельному разрешению владельца. Сверить суммы с первичными отчётами IDENT. До этой сверки не делать переключение финансовых отчётов.
6. Следующая дельта — Windows-отправитель: защищённое хранение SQL password/token (DPAPI/отдельная identity), согласованный persistent sequence, очередь и точные retry/ACK, один активный сборщик, защита при перезапуске, service auto-start до входа пользователя, проверка восстановления после пропадания сети и питания, дозагрузка пропущенных дат. Настройка BIOS power restore — отдельно. Ротация SQL fallback pin только с явным решением, без автоматического downgrade. Все эти механизмы ещё не реализованы.

## Синтетические проверки

Из этого каталога: python3 -m unittest discover -s tests -v. Для реального Gunicorn smoke в отдельном venv с requirements.txt: PYTHONPATH=. python3 tests/smoke_gunicorn.py. Тесты POSIX, непривилегированный пользователь. В CI нет реальных исходных данных, токенов, обращения к IDENT или к Production. Независимый аудит должен проверить транзакционность, ACL/инициализацию, восстановление, границы токена/организации, framing/size, конфликты, точность денег, ACK и неизменность действующей отчётности. Тестовый workflow находится только в изолированной CI-ветке; не сливать её в продукт.

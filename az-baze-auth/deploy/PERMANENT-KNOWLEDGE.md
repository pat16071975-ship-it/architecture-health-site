# Постоянные видео AZ-BAZE — подготовка и границы

Реализация отдельной ветки от ac10475c9ad2d7019e99b2a134b62357245713de.
Это не сообщение об установке, готовности 1233 видео или запуске массовой очереди.

## Контракт

- Просмотр общей готовой копии не запускает ffmpeg и не создаёт персональную очередь.
- Подготовка выполняется отдельно командой `prepare`; публикация — отдельным `publish`.
- До готовности ВСЕХ видимых видеоматериалов `active.json` не публикуется.
- Старые маршруты, права, идентификаторы и шаблоны сохраняются. Пока переменная
  AZBAZE_KNOWLEDGE_PERMANENT_ROOT не задана, рабочий код действует по-старому.
- При включённом постоянном режиме недоступное хранилище даёт 503, а не запускает
  скрытое перекодирование. Удаления готовых копий по лимиту/давности нет.
- SQLite-каталог используется только для чтения. Финансовые источники не меняются.

## Хранение

`--store` — явно выбранный существующий каталог на проверенном постоянном диске,
НЕ системный диск VPS, НЕ каталог исходников и НЕ его вложенная папка.
Он не создаётся и не монтируется автоматически. Пустой каталог маркируется `init`.
Внутри: `media/<исходные папки>/<имя>.mp4`, `archives/<исходные папки>/...zip`,
`state/items/<id>.json`, после полной проверки — `active.json`.
Архивы независимые ZIP64 без повторного сжатия видео, группировка по исходной
папке. Каждая часть раскрывается отдельно; исходные пути и имена внутри сохранены.
В архив попадают исходники, для которых готовится изменённая совместимая версия.
Полностью совместимый исходник используется непосредственно и не дублируется.
Архив и каждый его файл перечитываются и проверяются SHA256 до принятия результата.
Оригиналы НЕ удаляются и НЕ переносятся. Это увеличивает требуемое место:
архивы плюс новые копии — сверх уже хранимых исходников. Массовый запуск без
проверки полного запаса места запрещён. Предел архива по умолчанию 20 GiB —
техническая группировка файлов; один файл большего размера не разрезается.

## Проверки и незакрытые вопросы

- Реальные синтетические MOV/H264/AAC, MOV/PCM, MTS/AC3, HEVC8/10, MPEG4.
- Безопасность путей, атомарная публикация, восстановление прерванного задания,
  повторный запуск без перезаписи готового результата, ошибки/потеря диска.
- Проверки HTTP используют Flask и изолированную модель двух пользователей:
  разрешения, одинаковый файл, Range 206/416, отсутствие ffmpeg при просмотре.
  Это не независимая проверка боевой авторизации и не физический мобильный тест.
- Наличие субтитров, HDR, поворота, нескольких аудиодорожек, неизвестного кодека,
  проблемной длительности — блокер, а не повод молча выбросить данные.
- Совпадение хешей кадров не доказывает совпадение всех таймингов/синхронизации.
- CRF18 остаётся кандидатом. `publish` требует отдельной фиксации визуального
  согласования именно этого профиля (`--approve-visual-h264-crf18`). Просмотр
  автоматического 720p CRF23 не считается таким согласованием.
- 78 TIMEOUT + 1 PROBE_ERROR и 2 unknown из старого inventory не закрыты.

## Установка

Сначала standalone `knowledge-permanent-preflight.py` на root@az-server:
он только читает версии файлов, статусы, каталог и свободное место.
Секреты, окружение сервисов и сетевые реквизиты не печатает.
После результата готовится точная установка под фактический сервер: backup,
установка нового модуля и WSGI entry point, отдельная подготовка, проверка
архивов и готовности, затем переключение переменной окружения и HTTP-проверки.
Исходный server.py не изменён. При переключении Gunicorn использует
knowledge_permanent_wsgi:app вместо server:app. Старый worker останавливается
только при согласованном переключении, не раньше.
Данный пакет не меняет mount, не устанавливает сервис, не трогает Production.

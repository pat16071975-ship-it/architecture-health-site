## Контролируемая установка

Целевой сервер — `vdska`, сервис — `az-baze-auth`. Используется существующий
`/opt/az-baze-auth/venv/bin/python -B`.

Preflight сверяет каждый установленный файл с точной базой PR273, загружает
фиксированные исходники и проверяет Git blob каждого файла. Python проверяется
компиляцией, шаблоны — разбором Jinja. Рабочее приложение для этих проверок
не импортируется. Проверяются состояние сервиса, доступные GET-маршруты,
структура БД в режиме read-only и место для резервной копии.

В этом выпуске preflight загружает файлы из закреплённого фактического merge.
Проверка разрешения и корректного merge SHA выполняется до блокировки,
загрузки, остановки сервиса или создания резервной копии. Повторная проверка
находится непосредственно в функции применения.

После разрешённого выпуска четыре файла заменяются согласованным комплектом
при остановленном сервисе. До замены сохраняются исходные файлы с метаданными,
отдельный снимок SQLite и манифест. Установщик открывает рабочую БД read-only;
её байты и WAL сравниваются, пока сервис остановлен. Оригиналы документов,
черновики разбора и события истории установщик не изменяет.

После запуска проверяются состояние сервиса и защищённость GET-маршрутов.
Новый `/ocr/automatic/apply` проверяется как POST-only только после установки:
на базе PR273 этого маршрута ещё нет. Реальное распознавание и применение
товарных строк установщик не запускает.

При ошибке возвращаются прежние четыре файла с сохранением прав. Неожиданное
чужое содержимое не перезаписывается. Резервная БД автоматически поверх рабочей
не восстанавливается, чтобы сохранить действия пользователей после запуска.

## Фиксация выпуска

1. Перед merge подтверждены неизменные HEAD/BASE, PASS/CLOSE и 7/7 CI SUCCESS.
2. После merge сверены фактический SHA, дерево и Git blob четырёх файлов.
3. В отдельном установщике закреплены фактический `MERGED` и разрешение выпуска.
   Аудированные продуктовые файлы не менялись.
4. Установщик проверяется и публикуется отдельным операционным коммитом.
   Пользователь получает одну команду с проверкой его SHA-256.

Физическая установка считается подтверждённой только по серверному выводу
`PR274_RELEASE=PASS`. История текущего интерфейса показывает сведения о событии;
просмотр и восстановление архивной страницы из интерфейса пока не реализованы.
Приёмка реального документа остаётся отдельным шагом после выпуска.

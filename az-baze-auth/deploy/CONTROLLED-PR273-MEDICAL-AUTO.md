## Подготовка и применение

Целевой сервер: `vdska`, запуск от root существующим
`/opt/az-baze-auth/venv/bin/python -B`. Целевой сервис: `az-baze-auth`.

До остановки сервиса проверяются текущие файлы PR272, отсутствие новых
модулей, права сервиса, состояние приложения и совместимость зависимостей.
Рабочие файлы загружаются и сверяются по Git blob; Python и Jinja проверяются
без импорта рабочего приложения и без записи в рабочую БД.

Окружение Python подготавливается в отдельной полной копии существующего
venv. Устанавливаются только совместимые готовые wheels двух точных версий;
исходное окружение во время подготовки не меняется. Новые зависимости и
модули проверяются до остановки сервиса. Сетевые загрузки при остановленном
сервисе не выполняются.

SHA-256 выбранных wheels сверяется с метаданными соответствующего точного
выпуска на PyPI. Установка выполняется локально из этих wheels без подтягивания
других зависимостей. Состав остальных пакетов сравнивается с исходным; проверка
`RECORD` запрещает staged pip удалять файлы за пределами копии окружения.

`--preflight` выполняет подготовку и проверки с временными файлами, без
подмены рабочих файлов или окружения. `--apply` после этих же проверок
выполняет резервное копирование и установку. Команда запуска должна
проверять SHA-256 самого установщика до исполнения.

При применении сохраняются копии прежних рабочих файлов, отдельный снимок
SQLite и манифест выпуска. Сервис останавливается на замену файлов и
подготовленного окружения, затем запускается и проверяется через локальные
GET-маршруты. База открывается установщиком в режиме read-only; снимок
создаётся в отдельный файл. Неизменность основной БД и WAL проверяется,
пока сервис остановлен.

## Откат и границы результата

При ошибке применения установщик возвращает прежние рабочие файлы и
исходное окружение Python. Добавленные этим выпуском модули удаляются только
после проверки их ожидаемого содержимого. Резервная БД автоматически поверх
рабочей не восстанавливается. Чужое неожиданное содержимое не перезаписывается
при установке или откате.

Успешный результат установщика подтверждает установленный код, зависимости,
состояние сервиса и защищённость маршрутов. Приёмка распознавания реального
документа выполняется отдельно после установки. Уже сохранённые ручные
исправления имеют приоритет по правилам аудированного обработчика.
